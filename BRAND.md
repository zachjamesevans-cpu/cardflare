# CardFlare — Brand

## The logo

The approved CardFlare logo is the card-and-flare mark: a charcoal playing card
tilted forward, outlined in neon lime, with a flare burst on its face and a
flame trail streaming from its lower edge. There is no badge, disc, or
container around it.

**Master file:** `public/brand/cardflare-logo.png` — 1024 × 1024 canvas,
transparent, with the artwork occupying 581 × 721 of it (aspect **0.806**, so
the mark is **taller than it is wide**).

This file is byte-for-byte the approved original. It is never rewritten — not
even losslessly re-encoded, because passing it through an image pipeline drops
colour-profile chunks and is not bit-lossless.

**Do not redesign, reinterpret, redraw, replace, or modify the logo without
explicit approval.**

### Derivatives

Generated by `npm run brand:assets` from the master. The master's canvas has
uneven padding, so every derivative trims to the artwork's own bounds first and
then rebuilds padding appropriate to its context.

| File                              | Size    | Background  | Use                                  |
| --------------------------------- | ------- | ----------- | ------------------------------------ |
| `public/brand/cardflare-mark.png` | 413×512 | transparent | Header, footer, OG image             |
| `src/app/icon.png`                | 256×256 | `#12151b`   | Favicon (Next.js generates the rest) |
| `src/app/apple-icon.png`          | 180×180 | `#12151b`   | iOS home screen                      |

**Why the icons have a background.** The mark's card face is dark. A
transparent favicon disappears into a dark browser tab strip, and iOS opaques
home-screen icons anyway. Sitting the mark on the brand backdrop keeps it
legible on light and dark alike — verified at 16, 24, 32 and 64 px against both.
The on-page mark stays transparent, since the page is always dark.

### Usage rules

- The mark is **not square**. Size it by height and let width follow — the
  `Logo` component derives the ratio from the file itself, so a future master
  with different proportions stays correctly shaped. Never set both dimensions
  by hand.
- Always pair the mark with the "cardflare" wordmark unless space forbids it
  (`<Logo markOnly />`).
- Never stretch, recolour, rotate, or add effects to the mark.
- Alt text: the mark is decorative when the wordmark is present
  (`aria-hidden`), and labelled `"cardflare logo"` when it stands alone. This is
  handled by the `Logo` component — do not hand-roll `<img>` tags for it.

## The name

**Always lowercase: "cardflare".** The founder (2026-08-22, with the
current wordmark art): "make cardflare all lowercase. Website bar, etc
... Even the app name will be lowercase." That covers the header, the
footer, page titles, emails, the TV display, prose, and the app's
home-screen name. There is no context where "CardFlare" is correct any
more.

**The wordmark face is Audiowide** (Google Fonts, one weight), matched
to the same art. It is loaded as `--font-brand-display` on the web and
bundled as `Audiowide-Regular.ttf` in the app, and it is for the NAME
ONLY — body text, headings and buttons stay Inter. The wordmark is
drawn in the accent colour, whole; the old two-tone Card/Flare split
belonged to the previous mark.

## Colour

Sampled from the approved logo. Defined once in the `@theme` block of
`src/app/globals.css`; never write these hex values into a component.

| Token                     | Value     | Use                       |
| ------------------------- | --------- | ------------------------- |
| `--color-canvas`          | `#000000` | Page background           |
| `--color-surface`         | `#151a21` | Section and card surfaces |
| `--color-elevated`        | `#1d242d` | Raised controls           |
| `--color-border`          | `#2a323d` | Hairlines                 |
| `--color-border-strong`   | `#3a4553` | Hover / emphasis borders  |
| `--color-accent`          | `#c6ee4f` | Primary accent            |
| `--color-accent-hover`    | `#d3fa5f` | Bright accent state       |
| `--color-accent-contrast` | `#0e1116` | Text on accent fills      |
| `--color-text-primary`    | `#f2f5f7` | Headings, body            |
| `--color-text-secondary`  | `#b3becc` | Supporting copy           |
| `--color-text-muted`      | `#8593a4` | Metadata, captions        |
| `--color-success`         | `#6ee7a8` |                           |
| `--color-warning`         | `#fbc85a` |                           |
| `--color-danger`          | `#ff8f8f` | Form errors               |

Every text-on-surface pairing meets WCAG AA (≥ 4.5:1) and is enforced by
`tests/unit/design-tokens.test.ts`.

**The canvas is true black on purpose.** It was `#0e1116`, sampled from
the logo's badge, until the founder asked for "full black — will look
much cleaner". Everything above it stayed: `--color-surface` and
`--color-elevated` are unchanged, so a card now reads as raised off the
page rather than as a slightly lighter shade of it. `--color-accent-contrast`
is still `#0e1116` and should stay — it is the ink on a lime fill, not a
background, and pure black on that lime is harsher than the charcoal.

### Player avatar hues

| Token              | Value     |
| ------------------ | --------- |
| `--color-avatar-1` | `#8fd3ff` |
| `--color-avatar-2` | `#a8e6a1` |
| `--color-avatar-3` | `#ffc98f` |
| `--color-avatar-4` | `#d9b3ff` |
| `--color-avatar-5` | `#ffadad` |
| `--color-avatar-6` | `#7fe3d4` |

Assigned to a player by hashing **their player id**, so nobody reviews the pairing
before it appears next to their name.

It used to be the _session_ id, and the Feed disagreed with itself about
which: `hunt` and `added` seeded on the player id while `recent` and
`wanted` seeded on the session, so the same person wore two different
colours depending on which kind of card they turned up in. It is the
player id everywhere now, which also means somebody's colour follows
their account rather than resetting with a session. A guest has no
account, so their name is the seed — stable for as long as they use the
same one, which is as stable as a guest gets. Each one therefore has to clear AA on
canvas, surface **and** elevated, and the design-token test checks all
eighteen combinations plus that the token count matches `AVATAR_HUE_COUNT`.

Used only as foreground text over a tint of themselves, the same way `Badge`
works. **Deliberately not the accent**: an avatar must never be mistaken for a
CardFlare control. Adding or removing a hue means updating the tokens, the
constant, and `HUE_CLASS` in `player-avatar.tsx` together — Tailwind cannot see
a class name assembled at runtime.

**Note on the accent vs the mark.** The palette was sampled from the original
logo, whose brightest lime was `#d3fa5f`. The current master runs slightly
brighter and warmer at `#e0ff6c`. The two sit together without clashing, so the
tokens were deliberately left alone — changing `--color-accent` shifts every
button, link and heading on the site and re-opens the contrast budget. If you
want an exact match to the mark, that is a deliberate palette change: edit the
`@theme` block and re-run the design-token test.

## Typography

- **Sans:** Inter — headings and body.
- **Mono:** JetBrains Mono — reserved for card codes and identifiers.

Both loaded through `next/font` with `display: swap`.

## Voice

Direct, player-to-player, never hype. Short sentences. Say what the product
does, not how revolutionary it is.

- ✅ "CardFlare finds someone at the event who has it."
- ❌ "Revolutionising the way you trade!"

Be honest about stage: the product is being built, not launched. Never imply
CardFlare guarantees a trade, a price, or a card's authenticity.

## Visual direction

Dark charcoal-navy base, muted gray surfaces, faded neon-lime accent used
sparingly for emphasis. Rounded but not bubbly. Subtle glow on primary actions
only. High contrast, generous spacing, restrained motion.

Avoid: heavy gradients, particle effects, casino styling, anything childish.

# Working on CardFlare

Read [PRODUCT.md](./PRODUCT.md) and [ARCHITECTURE.md](./ARCHITECTURE.md) before
making changes. [BRAND.md](./BRAND.md) governs anything visual.

## Non-negotiables

- **Both platforms, always.** Any UI, copy, or feature change ships to the
  website AND the Expo app in the same round, matching as closely as the
  platform allows: same sections, same wording, same buttons, same order.
  The founder's standing instruction (2026-08-14): "all design changes and
  anything I say should also be programmed exactly the same for the app as
  well, unless I explicitly say otherwise." The app is the same product,
  not a companion.

- **A cosmetic's name never repeats its category.** The founder, twice:
  "no need to have 'edge' after everything... they should just be
  'frost', 'lava', etc" and then "I want that to apply to all future
  cosmetics that get added as well." Every cosmetic is shown under a
  heading that already says what it is, so the name carries the colour
  and nothing else: Prism, not Prism Edge; Galaxy, not Galaxy Holo;
  Ember, not Ember Name. `src/lib/players/cosmetic-names.ts` decides
  what counts as redundant and `tests/unit/cosmetic-names.test.ts`
  walks every name in every migration, so a new batch cannot ship with
  the fault. The one list that mixes categories, the pack odds table,
  re-adds the word only for names that genuinely collide.

- **Do not modify the logo.** `public/brand/cardflare-logo.png` is the approved
  master and is byte-for-byte the file that was supplied. Derivatives are
  generated by `npm run brand:assets`. The mark is taller than it is wide —
  size it by height and let width follow. See BRAND.md.
- **Do not expand product scope without approval.** PRODUCT.md lists what
  CardFlare is not. Milestones ship one at a time and stop for sign-off.
- **Do not ship fake functionality.** No placeholder buttons, no dead links, no
  social links to accounts that do not exist.
- **Do not claim something works without running it.** Run the commands.

## Rive cosmetics

A cosmetic is drawn one of two ways, and `cosmetics.art_kind` says
which. `css` means a `.cfa-<slug>` rule in `src/app/cosmetic-art.css`;
`rive` means the uploaded file at `rive_path`. A check constraint
refuses `rive` with no file and `css` with one.

Dropping one in: /admin/packs, "Drop in a Rive file" - file, name,
category. It lands as a draft, previews in the grid and in Customize,
goes live from the same tile, and joins a pack from the set builder.
Nothing about status, ownership, equipping or packs is special-cased
for Rive; that is the point.

- The runtime's WebAssembly is served from **our** origin
  (`public/rive/rive.wasm`, copied from the installed package by
  `scripts/copy-rive-wasm.mjs` in `prebuild`/`predev`, gitignored so it
  cannot drift). Never let it fall back to a CDN: the founder's network
  eats what it did not expect, and `tests/unit/rive-cosmetics.test.ts`
  fails if the fallback comes back.
- `@rive-app/canvas` is imported lazily inside `RiveArt`, so a page
  that draws no Rive cosmetic never downloads 1.8 MB of WASM.
- The app carries Rive files through its API but cannot play them yet:
  that needs the native runtime, which lands in its own round.

## Conventions

- Server Components by default. `"use client"` only where interactivity forces
  it, and keep those components small.
- Brand colours come from the `@theme` block in `src/app/globals.css`. Never
  write a literal hex value in a component. `tests/unit/design-tokens.test.ts`
  enforces contrast.
- Validate on the server. A Server Action is a public POST endpoint; client
  validation is a convenience only.
- Never let `SUPABASE_SERVICE_ROLE_KEY` reach a client bundle.
  `src/lib/supabase/admin.ts` imports `server-only` to make that a build error.
- Keep `src/lib/waitlist/form-data.ts` free of server-only imports so it stays
  unit-testable.
- `src/lib/supabase/types.ts` must use `type` aliases, not `interface` —
  supabase-js needs the implicit index signature that only type aliases get.

## Before declaring work done

```bash
npm run verify      # format, lint, typecheck, unit tests, production build
npm run test:e2e    # Playwright
```

In sandboxes with a preinstalled Chromium of a different build, set
`PLAYWRIGHT_CHROMIUM_PATH` rather than downloading browsers.

E2E tests needing a live database skip with a reason instead of failing. If you
change the waitlist path, say plainly which tests ran and which skipped.
